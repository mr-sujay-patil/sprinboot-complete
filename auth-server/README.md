# Auth Server Microservice

A simple Spring Boot 3.x Authentication Microservice using Spring Security, JWT (JSON Web Tokens), and an H2 in-memory database. Designed for learning purposes.

## Quick Start

**Prerequisites:**
- Java 21 or higher
- Maven 3.8+

**How to run:**
1. Navigate to the project root directory.
2. Execute the following command:
   ```bash
   mvn spring-boot:run
   ```
3. The server will start on port `9090`.

## Available Endpoints

| Method | Endpoint | Description | Access |
|---|---|---|---|
| POST | `/api/auth/register` | Registers a new user and returns a JWT | Public |
| POST | `/api/auth/login` | Authenticates a user and returns a JWT | Public |
| GET | `/api/test/public` | A public test endpoint | Public |
| GET | `/api/test/secured` | A secured test endpoint | Requires valid JWT |

## CRITICAL SECTION: How Another Microservice Validates Tokens from This Server

In a microservices architecture, this Auth Server generates tokens, and other microservices (Resource Servers) validate them to grant access to protected resources.

### A. The Shared-Secret Approach (Symmetric)
This project uses a **Shared-Secret** approach (HMAC algorithm). Both the Auth Server (which signs the token) and the consumer microservice (which validates it) must share the exact same `jwt.secret` property. 
* **Trade-off:** It is simple to implement but carries a security risk. If any consumer service's configuration is compromised and the secret is leaked, the attacker can generate valid tokens for the entire system.

### B. Steps for the Consumer Microservice

To validate tokens generated by this Auth Server, a consumer microservice must implement the following:

1. **Add JJWT Dependencies:** Add `jjwt-api`, `jjwt-impl`, and `jjwt-jackson` to its `pom.xml` (same as this auth server).
2. **Create a JwtUtil:** Create a utility class that initializes the parser using the **SAME** `jwt.secret` key to verify the token signature and extract claims (like username and roles).
3. **Create a JwtAuthenticationFilter:** Create a filter extending `OncePerRequestFilter`. It intercepts every request, extracts the Bearer token from the `Authorization` header, uses `JwtUtil` to validate it, and creates a `UsernamePasswordAuthenticationToken` to set in the `SecurityContextHolder`.
4. **Configure SecurityFilterChain:** Configure Spring Security to be stateless (`SessionCreationPolicy.STATELESS`) and insert the `JwtAuthenticationFilter` before the standard `UsernamePasswordAuthenticationFilter`.
5. **No Database Needed:** The consumer microservice **does NOT need a `UserDetailsService` or a database connection to the users table**. It trusts the claims embedded in the JWT (e.g., username, roles) because the signature proves the token was issued by the trusted Auth Server and hasn't been tampered with.

### C. Asymmetric Key Alternative (RS256)
For production systems, an **Asymmetric Key (RSA)** approach is recommended. 
* The Auth Server holds a **Private Key** used ONLY to sign tokens.
* Consumer services hold a **Public Key** used ONLY to verify tokens.
* This is far more secure because even if a consumer service is compromised, the public key cannot be used to forge new tokens.

### D. Code Skeleton: Consumer-Side Filter

Here is a simplified example of the filter required in the consumer microservice (~20 lines):

```java
import jakarta.servlet.*;
import jakarta.servlet.http.*;
import org.springframework.security.authentication.UsernamePasswordAuthenticationToken;
import org.springframework.security.core.context.SecurityContextHolder;
import org.springframework.web.filter.OncePerRequestFilter;
import java.io.IOException;
import java.util.Collections; // Or parse roles from token claims

public class JwtAuthenticationFilter extends OncePerRequestFilter {
    private final JwtUtil jwtUtil; // Injected utility configured with the shared secret
    
    public JwtAuthenticationFilter(JwtUtil jwtUtil) { this.jwtUtil = jwtUtil; }

    @Override
    protected void doFilterInternal(HttpServletRequest request, HttpServletResponse response, FilterChain chain) 
            throws ServletException, IOException {
        String header = request.getHeader("Authorization");
        if (header != null && header.startsWith("Bearer ")) {
            String token = header.substring(7);
            if (jwtUtil.validateToken(token)) {
                String username = jwtUtil.extractUsername(token);
                // Create auth object (trusting the token, no DB lookup needed)
                var auth = new UsernamePasswordAuthenticationToken(username, null, Collections.emptyList());
                SecurityContextHolder.getContext().setAuthentication(auth);
            }
        }
        chain.doFilter(request, response);
    }
}
```

## Limitations

- **Learning Project:** This codebase is intended for educational purposes.
- **In-Memory DB:** Data is not persisted across application restarts.
- **Roles:** Role management is simplified to a comma-separated string rather than a normalized relational schema.
- **Secret Management:** The JWT secret is hardcoded in the configuration file. In production, secrets must be injected via environment variables or a secrets manager (e.g., HashiCorp Vault, AWS Secrets Manager).
